# Portfolio source stabilization for AI-SDLC 2.4.1

**Status:** consumer candidate; the organization `ai-sdlc-v2.4.1` tag is not
published.

This change narrows source responsibility without changing the closed v2 task
payload or the retained v2 result projector.

- An authorized human adding `status:approved` is the only approval action.
- The issue form no longer contains an execution-status authority field.
- The workflow re-reads the issue and compares the complete material task
  identity from the label event with current authority. It does not compare
  incidental `updated_at` values.
- Any issue edit removes approval and projects `status:proposed`.
- The source validates target repository syntax only. The organization registry
  is the sole target-membership and activation authority.
- The organization router is the sole admission-marker writer. The source writes
  only the queued lifecycle projection after successful routing.
- The retained result projector slurps every issue-comment page before checking
  admission and result markers.
- The reusable router pin is `ai-sdlc-v2.4.1`.

Do not merge this consumer until the immutable `ai-sdlc-v2.4.1` control-plane
tag resolves. Merge it during a controlled approval freeze, then resume
approval-label activity only after Runtime Preflight passes. This prevents
approved label events from being stranded against an unavailable workflow.
