## Why this cutover is required

REAL issue #159 proved the dedicated GitHub App result-writer prerequisite path
healthy but exposed DEF-0073 when the immutable 3.0.0 receiver rejected a valid
3.0.1 admission solely because the admission's control-plane release differed
from the receiver implementation release.

Published 3.0.2 replaces that accidental equality check with an immutable
receiver-owned compatibility allowlist. The policy explicitly accepts 3.0.1
admissions required to recover the already-admitted #159 delivery and accepts
3.0.2 admissions for new work after this source cutover. Unsupported release
combinations remain fail-closed.

## Safety and execution boundary

Merging this consumer pin does **not** itself perform a cost-bearing Codex
execution. After merge:

1. reconcile the latest failed #159 target attempt first if the source remains
   queued/nonterminal;
2. re-authorize the unchanged #159 issue through the existing human approval
   action;
3. require the 3.0.2 router and immutable target to preserve the existing
   logical delivery/correlation identity;
4. require one corrected receiver/source terminal projection;
5. re-authorize the unchanged delivery once more;
6. require `duplicate-reused` before Codex; and
7. verify no second Codex execution, branch, managed draft, receiver forwarding
   effect, or source terminal projection occurs.
